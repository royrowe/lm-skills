# PRD 生成（含角色工作拆解）

用户（2026-08-27 确认）对 PRD 的硬性要求：

> 「写一份prd，请写清楚客户端、服务端、cms、设计师、测试工程师、前端工程师分别需要针对这项需求完成的工作，如果不涉及到以上某些工种的工作不必强行书写，有什么问题可以问我。」

## 三条核心规则

1. **每项需求都附「角色工作拆解」**：PRD 中每一条需求，都要写清楚六个工种中实际涉及的工种分别要完成什么工作。
2. **不涉及的工种不写**：某项需求不涉及某工种时，直接省略该行——不写「无」「不涉及」占位，不为了凑满六行而编造工作。这条规则的用意：拆解表会被直接拿去给各工种分配任务，编造出来的工种工作会浪费评审和执行时间。
3. **有疑问先提问**：需求有歧义或缺少关键细节时，先向用户提问澄清，拿到答复后再动笔，不自行假设。假设出来的需求到评审时会被打回，返工成本远高于先问一句。

## 工作流程

### 第 1 步：检查需求完整性，有缺口先提问

动笔前逐项检查：目标用户/使用场景、平台（App / Web / 小程序 / 管理后台）、是否涉及 CMS 配置、数据从哪来（服务端接口还是写死）、验收标准是否可量化、边界情况是否说清。

发现缺口时，用 AskUserQuestion 或对话集中提问，问题要具体（比如「领券入口是在 App 内还是 H5 活动页上？」），而不是笼统地问「还有补充吗」。直到关键缺口补齐，或用户明确表示「按你的理解写」，才继续。

### 第 2 步：按结构写 PRD

```
# 一、需求概述
背景与目标 / 目标用户 / 非目标（本次不做的事）

# 二、需求明细
每项需求单独一节，包含：
- 需求描述：做什么、什么场景、什么效果
- 验收标准：可量化
- 角色工作拆解：见第 3 步
```

### 第 3 步：为每项需求写「角色工作拆解」

用表格，每行一个角色：

| 角色 | 工作内容 |
|------|----------|
| 客户端 | 具体要做的开发/集成工作 |
| 服务端 | 具体接口、逻辑、存储工作 |
| CMS | 具体要配置/开发的后台能力 |
| 设计师 | 具体要出的设计稿/规范 |
| 测试工程师 | 具体要写的用例/要做的测试 |
| 前端工程师 | 具体要做的 Web/H5/后台页面工作 |

只保留实际涉及的角色行。工作内容要具体到「这个工种必须交付什么」——例如服务端写「新增 /api/xxx 接口，返回字段 a/b/c」，而不是「提供接口支持」。

## 判断某需求是否涉及某工种的依据

看该需求上线时，这个工种是否必须交付产出物（代码 / 接口 / 配置 / 设计稿 / 测试用例）：

- **客户端**：涉及 App（iOS/Android）页面、交互、推送、SDK 接入、机型适配时涉及。
- **服务端**：涉及接口、业务规则计算、数据存储/上报、风控、推送下发时涉及。纯本地展示、数据写死的不涉及。
- **CMS**：涉及运营后台配置（文案、活动、开关、运营位、内容管理）时涉及。全部写死在客户端/服务端的不涉及。
- **设计师**：涉及新页面、新组件、视觉改版时涉及。纯逻辑/接口类需求（如埋点、数据修复）通常不涉及。
- **测试工程师**：几乎每条需求都涉及（用例 + 验证），但若用户明确说明某条需求不需测试，则不写。
- **前端工程师**：涉及 Web 前端、H5、管理后台页面时涉及。纯 App 原生需求不涉及。

## 注意事项

- 需求描述里没提到的角色，不代表自动涉及——按上面的判断依据逐个过一遍，而不是默认六行全写。
- 同一需求的拆解表里，各角色工作要能衔接（设计师出稿 → 客户端/前端实现 → 测试验证），有依赖的写清交付顺序或接口约定。
- 输出全中文。

## 示例

**需求**：App 活动页新增「邀请好友领券」入口（券由运营配置，活动页为 App 原生页面）。

| 角色 | 工作内容 |
|------|----------|
| 客户端 | 活动页新增邀请入口，点击拉起分享；被邀请人进入领券页并调起领券接口 |
| 服务端 | 新增邀请关系绑定接口与领券接口，校验邀请资格与券库存 |
| CMS | 提供活动运营位配置：入口文案、图片、券的上下架 |
| 设计师 | 提供入口位与领券页视觉稿、分享图素材 |
| 测试工程师 | 用例覆盖邀请链关系、重复领取、库存耗尽、分享图生成 |

（前端工程师不涉及——活动页为 App 原生，无 H5/Web 页面。）

**需求**：新增订单埋点上报，用于运营分析。

| 角色 | 工作内容 |
|------|----------|
| 客户端 | 在支付成功页等节点按规范埋点并上报 |
| 服务端 | 提供埋点接收接口，入库并输出到数据分析表 |
| 测试工程师 | 验证各节点埋点触发与数据落库的准确性 |

（CMS、设计师、前端工程师不涉及——无页面改动、无后台配置。）
