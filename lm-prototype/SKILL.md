# 前端产品原型生成器

本技能用于根据用户的产品需求，快速生成高质量的前端原型页面。

## 核心原则

- 始终生成**可独立运行**的 HTML 文件 —— 一个完整的 HTML 文件包含所有内联 CSS 和 JS，用户双击即可在浏览器中查看
- 所有第三方资源必须**本地化** —— 绝不允许引用 CDN。将字体、图标库、JS 框架等以合适方式内联或本地储存
- 注重**真实感** —— 使用合理的测试数据、真实的文本内容，而非 "Lorem ipsum"

## 原型架构设计

生成原型前，先分析产品需求并确定以下内容：

1. **功能模块拆解** —— 产品由哪些核心功能组成？每个功能对应哪些页面/区域
2. **信息架构** —— 页面之间的层级关系和导航逻辑
3. **用户流程** —— 用户从进入到完成目标会经历的步骤
4. **交互状态** —— 每个页面/组件需要展示哪些状态（正常、空数据、错误、加载、成功）

### 设备适配

根据用户需求决定生成方式：

- **明确要求手机版** → 生成手机外框（375×812 或类似比例），所有内容（包括弹窗、Toast）限制在手机框内，手机框居中显示在页面中央
- **明确要求 PC 版** → 生成 PC 端页面，宽屏布局
- **没有明确说明** → 同时生成手机版和 PC 版，采用**一个 HTML 文件、双视图切换**的方式：顶部提供「手机版 / PC 版」切换标签，默认展示 PC 版

手机外框样式参考：
```css
.phone-frame {
  width: 375px;
  height: 812px;
  border-radius: 40px;
  border: 3px solid #333;
  box-shadow: 0 0 30px rgba(0,0,0,0.3);
  overflow: hidden;
  position: relative;
  background: #fff;
}
```

## 页面输出结构

在调用本技能的项目的根目录下创建 `prototype/` 文件夹，将所有文件平铺在内：

```
prototype/
├── index.html          # 主入口页面（包含所有原型内容）
├── index.js            # 交互逻辑
├── index.css           # 样式文件（如果样式较多时单独抽出）
└── assets/             # 静态资源（图片等，如果需要）
```

**关键要求：** `index.html` 必须是自包含的 —— CSS 和 JS 优先内联写在 HTML 中，只有当代码量较大（超过 200 行）时才单独抽出为 `.css` / `.js` 文件。这样确保用户可以直接双击 HTML 文件预览。

## 图标系统

使用 **Lucide Icons** —— 将需要的 SVG 图标直接内联嵌入 HTML 中：

- 从 [Lucide Icons](https://lucide.dev/icons/) 获取 SVG 代码
- 图标必须继承文本颜色：使用 `currentColor` 作为 `stroke` 颜色
- 统一尺寸：常用 16px/20px/24px，根据上下文选择

内联方式示例：
```html
<svg xmlns="http://www.w3.org/2000/svg" width="20" height="20" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-search">
  <circle cx="11" cy="11" r="8"/><path d="m21 21-4.3-4.3"/>
</svg>
```

**禁止使用** `<i data-lucide="..."></i>` 这种需要加载 lucide.js 库的写法 —— 必须内联 SVG。

## 图片资源

- 图片使用data:image/svg+xml的方式占位；
- 如有特殊需求，使用 [picsum.photos](https://picsum.photos) 获取占位图片，图片下载至本地：
- - 固定尺寸：`https://picsum.photos/400/300`
  - 正方形头像：`https://picsum.photos/100/100`
  - 随机产品图：`https://picsum.photos/600/400`
- 传入 `?random=N` 参数获取不同图片，避免重复
- 所有图片保存本地；

## 测试数据

原型页面必须包含合理的测试数据，让观看者能理解页面的功能和布局：

- 使用中文模拟数据（除非用户要求其他语言）
- 数据应覆盖各种状态：正常列表、模块结构、用户头像占位等
- 额度/数字等数据应合理：用户数可用 1,234 或 9.5k 这类真实感的数值
- 人名、部门名、任务名等使用中文常见名称
- 表格数据至少 3-5 行

## 交互与脚本

JavaScript 应实现以下交互（根据原型需要选择）：

- **页面切换/标签切换** —— 手机版/PC版切换、Tab 切换、侧边栏展开收起
- **模态框/弹窗** —— 新增/编辑表单、确认删除、详情查看
- **下拉菜单** —— 用户头像下拉、操作菜单
- **表单验证** —— 必填项检查、格式校验的视觉反馈
- **Toast 消息** —— 操作成功/失败的轻提示
- **数据筛选/搜索** —— 列表过滤、搜索高亮

所有 JS 使用原生 JavaScript（不依赖框架），交互代码应简洁清晰。

## 设计风格

参考现代企业级产品的设计风格：

- **颜色**：使用 CSS 变量定义主色、辅色、背景色、边框色、文字色
- **间距**：保持一致的内边距和外边距（4px/8px/12px/16px/20px/24px/32px 系列）
- **圆角**：统一使用 4px/6px/8px/12px 系列
- **阴影**：轻量阴影增加层次感，避免过重
- **字体**：系统默认字体栈 —— `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
- **响应式**：PC 版使用 flexbox/grid 布局，手机版适配 375px 宽度

## 输出前检查清单

在交付原型文件前，确认：

1. [ ] HTML 文件可以独立打开运行（不依赖本地服务器）
2. [ ] 没有 CDN 引用（图片除外）
3. [ ] Lucide 图标已内联为 SVG
4. [ ] 测试数据真实可读（中文、合理的数值）
5. [ ] 交互功能（切换、弹窗等）可以正常触发
6. [ ] 手机版（如有）限制在手机框内，弹窗也在框内
7. [ ] 所有文件正确写入 `prototype/` 目录下
